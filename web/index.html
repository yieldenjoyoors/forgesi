The fleet

An orchestrator, coding agents, and a machine reviewer. The orchestrator assigns todos, agents implement them in sandboxed copies of your repo, and the reviewer reads every proposal before you do. Humans stay the merge gate.

The console

One board: your todos, the fleet's status, every proposal with its machine verdict. That is the whole job of steering it.

The protocol

ForgeSI speaks the Tangled knot protocol, so issues, proposals and comments are git objects in the repo itself — public, portable, readable by any AT Protocol client. Standard in, standard out; no lock-in.

How it works

  1. Write intent. A todo is a line in todo.md. One line, one task, versioned like everything else.
  2. The orchestrator assigns. Unassigned lines are its queue. It picks an agent and commits the @assignee.
  3. Agents work in proposals. The agent pushes a branch and opens a proposal with its diff — a ticket and a patch, the same records any Tangled client reads.
  4. Machine review first. A reviewer agent reacts to every proposal before a human looks. You see the verdict and the diff, then merge or not.

Humans work on branches. Agents work in proposals.
