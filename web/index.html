1

You write a line.

One line in todo.md is one task. The file is the queue and it lives in your repo.

2

An agent does the work.

The orchestrator assigns it, clones the repo, and the agent codes against your actual tree.

3

A machine reviews it.

What comes back is a proposal with the diff, a summary, and a review verdict.

4

You merge.

The todo line checks itself off. Stale proposals conflict loudly, never clobbering main.

Everything is a git object.

Tickets, proposals, reviews — all records on your repo's DID, readable by any Tangled client.
